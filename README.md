# Man Authority — Frontend

Premium, responsive, server-rendered frontend for the Man Authority personal
authority website.

**Frontend only.** There is no backend, database, auth, CMS, payments, search
engine or email delivery in this repository. Every data source is a typed mock
module and every form resolves against a simulated request, so real APIs can be
dropped in later without touching component code.

---

## Stack

| Concern    | Choice                                       |
| ---------- | -------------------------------------------- |
| Framework  | React 19 + TanStack Start (SSR) + TanStack Router |
| Language   | TypeScript (strict)                          |
| Build      | Vite 7                                       |
| Styling    | Tailwind CSS v4 (CSS-first `@theme` tokens)  |
| Primitives | shadcn/ui-style components on Radix UI       |
| Motion     | Framer Motion                                |
| Forms      | React Hook Form + Zod                        |
| Icons      | lucide-react                                 |

## Getting started

```bash
npm install
npm run dev        # http://localhost:3000
```

| Script              | Does                                                  |
| ------------------- | ----------------------------------------------------- |
| `npm run dev`       | Vite dev server with SSR + HMR                        |
| `npm run build`     | Production build → `dist/client` + `dist/server`      |
| `npm start`         | Serves the production build on `PORT` (default 3000)  |
| `npm run typecheck` | `tsc --noEmit`                                        |

`npm start` uses `server/index.mjs`, a dependency-free Node adapter around the
web-standard `fetch` handler that the build emits. Replace it with a platform
preset (Vercel / Netlify / Cloudflare / Bun) at deploy time — the handler it
wraps is identical.

> Node 22.12+ is recommended. TanStack Start declares it as its engine
> requirement; the app builds and renders on Node 20 but you will see
> `EBADENGINE` warnings on install.

## Design system

All tokens live in one place: the `@theme` block in
[`src/styles/app.css`](src/styles/app.css). They compile into ordinary Tailwind
utilities, so `--color-gold-400` is usable as `bg-gold-400`, `text-gold-400`,
`border-gold-400`, and so on.

### Colour

| Scale         | Range           | Used for                                    |
| ------------- | --------------- | ------------------------------------------- |
| `ink-400…950` | `#4d4d4d`→`#050505` | Dark sections, navbar, footer, hero backdrops |
| `gold-50…800` | `#fbf7ef`→`#5f411a` | Accent, CTAs, eyebrows, icons, focus ring |
| `cream-50…400`| `#ffffff`→`#e2dad0` | Light sections, cards, hairlines         |

Semantic text tokens: `text-heading`, `text-body`, `text-muted`.

### Typography

- **Display** — Playfair Display (`font-display`) for headings and stat figures
- **Body / UI** — Inter (`font-sans`)
- **Signature** — Dancing Script (`font-script`), used for Brian's signature

Fluid display sizes clamp between mobile and desktop and carry their own
line-height and tracking: `text-display-xl`, `-lg`, `-md`, `-sm`, plus
`text-eyebrow` for the uppercase gold labels.

### Spacing & layout

`Container` (max `1320px`), `Section` (tone + vertical rhythm), and `Grid`
(responsive column presets) are the three layout primitives. Every page is built
from them, so global spacing changes are one-line edits.

### Motion

Four primitives cover the whole site, all of which collapse to static markup
under `prefers-reduced-motion`:

| Component        | Use                                       |
| ---------------- | ----------------------------------------- |
| `Reveal`         | Scroll-triggered fade + translate (fires once) |
| `Stagger` / `StaggerItem` | Cascading grids and lists        |
| `TextReveal`     | Word-by-word hero headlines               |
| `PageTransition` | Route enter transition (applied in `__root`) |

Hover, card lift and image zoom are pure CSS transitions so they cost nothing
during scroll.

## Data & the API seam

Everything under `src/data/` is a typed module shaped like a CMS response:

| Module                        | Feeds                                     |
| ----------------------------- | ----------------------------------------- |
| `site.ts`                     | Brand, contact details, socials, channels |
| `navigation.ts`               | Navbar, mega menu, mobile drawer, footer  |
| `articles.ts`                 | Blog listing, article page, related posts |
| `home / about / expertise / speaking / ai-business` | Page content       |
| `testimonials.ts`, `faqs.ts`, `legal.ts` | Shared blocks              |

`articles.ts` exposes query helpers — `queryArticles`, `getArticleBySlug`,
`getRelatedArticles`, `getPopularArticles` — that mirror the shape of a real
list/detail endpoint. Point them at `fetch` (or move them into route loaders as
server functions) and no component changes.

Forms follow the same pattern: validation, pending, error and success states are
already wired; only the request itself is mocked, in
[`use-mock-submit.ts`](src/components/forms/use-mock-submit.ts) and the
newsletter form's `submit`.

### Images

This build ships without binary assets. `ImageFrame` reserves the correct aspect
ratio and paints a deterministic, on-brand gradient placeholder with film grain.
Pass a `src` and it renders a lazy, async-decoded `<img>` in the same box — no
layout shift, no other changes:

```tsx
<ImageFrame seed={article.slug} ratio="aspect-[4/3]" zoomOnHover />
<ImageFrame src="/img/hero.jpg" alt="Brian on stage" ratio="aspect-[4/3]" priority />
```

## Routing notes

- Blog filters live in **search params** (`/blog?category=fitness&page=2`), so a
  filtered view is shareable, bookmarkable and survives a refresh. They are
  validated in `blog.index.tsx`'s `validateSearch`.
- `blog.$slug.tsx` resolves the article in a `loader` and throws `notFound()` for
  unknown slugs, which lets `head()` emit real per-article Open Graph tags.
- `AppLink` ([`ui/app-link.tsx`](src/components/ui/app-link.tsx)) is the single
  bridge between data-authored `string` paths and the router's typed path union;
  it also renders plain anchors for `http`, `mailto:` and `tel:` targets. Static
  in-code links use `Link` directly and stay fully type-checked.

## Responsive & accessibility

Mobile-first throughout, with breakpoints at `sm` 640 / `md` 768 / `lg` 1024 /
`xl` 1280. The desktop nav collapses into a Radix Dialog drawer below `xl`; the
career timeline flips from a horizontal rail to a vertical one below `lg`.

Targeting WCAG 2.1 AA:

- Semantic landmarks (`header`, `nav`, `main`, `aside`, `footer`, `article`) and
  a real heading outline on every page
- Skip-to-content link as the first focusable element
- Visible gold focus ring on every interactive element (`:focus-visible`)
- Radix handles focus trapping, `aria-modal`, scroll lock and Escape in the
  mobile drawer, and the roving focus + ARIA wiring in every accordion
- Labels on all fields (visually hidden where the design uses placeholders),
  `aria-invalid`, `aria-describedby`, and `role="alert"` on error messages
- Decorative icons and placeholder art are `aria-hidden`
- `prefers-reduced-motion` disables every animation and smooth scroll

## Performance

- SSR on every route, with per-route code splitting
- Heavy vendors (`framer-motion`, Radix, forms, icons) are split into separate
  long-lived chunks via `manualChunks` so a content edit never invalidates them
- `defaultPreload: 'intent'` prefetches on hover/focus
- Images lazy-load and decode async by default; hero art opts into
  `priority` for `fetchpriority=high`
- Placeholder art is inline SVG/CSS — zero extra requests
- Fonts preconnect and use `display=swap`

## Not included (by design)

Every one of those has a clearly marked seam in the code where it plugs in.
